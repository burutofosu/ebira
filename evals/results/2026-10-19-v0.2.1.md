## What went wrong

- **A question the records do not settle gets no answer.** When the screen finds nothing
  relevant, `ask` returns `no_records` and says nothing, where it should say that nothing
  was found and what came closest (F1 and F5, half the point each). In F3 ("when did I
  publish ledger-cli?") the search for 公開 found the agent's reply 公開するときは README と
  LICENSE を整えましょう; the screen, which sees the record and not the person's
  そのうち crates.io に出したいな just before it, scored it irrelevant, so the answer missed
  that the person only wished to publish.
- **`--quick` searched for a string without the space the record has.** The plan asked for
  csv取り込み; the person wrote CSV 取り込み. Nothing was found and A1 got no answer. The
  default models chose strings that matched. Japanese text often has a space between Latin
  letters and kana or kanji, and often does not.
- **`--quick` missed later changes made in other words** (C4, C5) and a later decision that
  replaced an example (B3): it has no second round of searching and no check for later
  changes, which the default models have. This is the trade the help describes ("more
  mistakes about what changed later"), here in numbers.

## Reading these numbers

The default models made every key point outside `no_record`: on logs this small, the
search reaches every case, and the five kinds of reading these cases test are not where
they fail. The room left is in answering when there is nothing to answer from, and, for
`--quick`, in the strings it searches for. One run each: the strings a model chooses vary
from run to run.
