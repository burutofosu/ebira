commit 5142146 on top of 0.2.1 (not released). It makes two changes to `ask`: every search
string is also searched with a space and with none between Latin letters or digits and
Japanese, and when the screen judges none of the records found relevant, `ask` says first that
the records found do not settle the question, with the strings searched and how many records
they found, and answers from the closest of them. The models are the same as for 0.2.1. The
answers were judged blind, as [JUDGE.md](../JUDGE.md) says, by a Claude Code subagent for each
run, given only JUDGE.md and the answers in a folder with a neutral name. No judgment was
corrected by hand.

## What the fixes did

- **A question the records do not settle now gets an answer that says so.** Where no record
  holds any search string (F1 both ways, F4 and F5 with `--quick`, and B2 and C2, below), the
  result now says that, with the strings searched and the directory searched, instead of
  giving an empty answer.
  F1 and F5 went from half the point to the whole point. In F5 with the default models, the
  string /mo found 12 records, all naming `src/models.py`. The screen judged none relevant, so
  the answer read the 8 closest and said they hold nothing about a price (`nothing_relevant`).
  In F3 with `--quick`, the first round found only the agent's replies holding 公開, and the
  screen judged them unrelated. The draft, written from the closest of them and the records
  around them (the person's そのうち crates.io に出したいな comes just before one), suggested
  crates.io. The second round found that message, the screen kept it, and the answer made both
  key points (0.2.1: none). With the default models, the plan chose crates.io itself this
  time, so F3 went through the ordinary path.
- **`--quick` finds a string written with the other spacing.** The strings `--quick` chose for
  A1 in the 0.2.1 run, searched with this build without the API, find the person's
  CSV 取り込み作って… through the variant csv 取り込み, where 0.2.1 found nothing. In this run
  the plan chose csv取り込, and its variant csv 取り込 found the same record. So did 取り込み,
  which the plan also chose, so A1's three key points (0.2.1: none) are not the variant's alone.

## What did not change, or got worse

- **When nothing at all is found, `ask` does not try other strings.** With `--quick`, B2 and
  C2 got no answer beyond the statement: the plan chose phrases such as タグの仕様,
  ログイン方式 and 認証方式, and words the person never wrote (oauth, passkey), and no record
  holds any of them. With nothing found there is no draft, so there is no second round. In
  the 0.2.1 run the plan also chose タグ and ログイン. F4
  lost its second point the same way: no string was 効果音 alone, so the agent's statement that
  the sound effects are CC0 material was not found. These three cases account for 6 of the 7
  key points `--quick` missed. The fixes do not cause this, but a plan whose strings all find
  nothing is the next thing to address.
- **The other `--quick` differences are variance.** B3, C4, and C5 had a mistake each in the
  0.2.1 run and none here; B3 and C4 made every key point, and C5 and A3 gained half a point.
  D2 lost half a point. This commit adds no check for later changes to `--quick`, so these
  come from the strings and the readings of one run.
- **The closest records can bring a finding that does not bear on the question.** The default
  models' F5 answer listed the person's request to rename the functions in `src/models.py` as a
  finding. It is not a mistake, since the answer says that nothing there is about a price, but
  it adds noise.

## Reading these numbers

On these logs the default models now make every key point. The cases cannot tell their
setup from a better one any more, only from a worse one. The fixes account for the gains in
`no_record`: F1 and F5 both ways, and F3 with `--quick`. In each of those, the result shows
the statement of what was searched, or the closest records read. F3 with the default models
and A1 with `--quick` gained mostly from the strings the plan chose this time, though the
variant found A1's record too. One run each: most other differences between the two
`--quick` runs come from the strings the plan chose. Spacing variants add strings to the
same pass over the corpus, at most two for each string chosen. The default run cost 4 cents
more than the 0.2.1 run, and the time a question took did not change.
