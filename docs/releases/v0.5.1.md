# Ebira 0.5.1

`ebira ask` reads your messages in the three ways that measured best, now by default.

- The screen sees each of your messages with the end of the agent's reply before it and the
  agent's last reply in its turn, so that a short reply ("go with that", "じゃあそうして")
  is judged by what it answered.
- A long message is screened in overlapping pieces, and the answer is shown the piece judged
  relevant, not only the message's head and tail.
- The answer gets the relevant records the higher score first and one session at a time. The
  digest of your other relevant messages gives identical ones once with their count, within a
  character budget, instead of the earliest and the latest 300.

On the evaluation's fifty-four questions, the answers made 100% of the key points instead of
95%, and none made a mistake instead of two, at the same cost: the differences are an
agreement nothing else names, the middle of a long pasted spec, and rules repeated among
hundreds of remarks. On six questions about the author's history, they made 83% instead of
89%, which one run each cannot tell apart. The
[measurements](https://github.com/burutofosu/ebira/blob/v0.5.1/evals/results/2026-10-20-delivery.md)
say what each way kept and cost.

`--no-sweep-context`, `--no-sweep-chunks`, and `--delivery current` read as 0.5.0 did.
`--sweep-context` and `--sweep-chunks` are gone: what they turned on is the default.

From this release, versions move their last number; the middle one moves only for a large
change.

See [CHANGELOG.md](https://github.com/burutofosu/ebira/blob/v0.5.1/CHANGELOG.md)
for the full list.

## Upgrading

The corpus stays as it is: no rebuild is needed.

## Install

From source, with Rust 1.89 or later:

```sh
cargo install --locked --git https://github.com/burutofosu/ebira --tag v0.5.1
ebira sync
```

For a binary archive, extract it and put `ebira` or `ebira.exe` on `PATH`.
SHA-256 checksums for both archives are listed in `SHA256SUMS.txt`.
The archives include the license, README, changelog, example transcript, and
agent skills.

## Agent skills

- Claude Code: copy the individual directories from `skills/claude` into `~/.claude/skills`.
- Codex: copy the individual directories from `skills/codex` into `~/.agents/skills`.

Keep each skill's `SKILL.md` and supporting files together. These locations
follow the [Claude Code skills guide](https://code.claude.com/docs/en/skills)
and the [Codex skills guide](https://learn.chatgpt.com/docs/build-skills).

## Compatibility and data

The package workflow builds Linux x86-64 and Windows x86-64 binaries, the
platforms verified for this release. The Linux build uses Ubuntu 22.04 and
glibc; it does not target musl-based distributions such as Alpine.

The binaries are unsigned.
Windows Smart App Control may block unsigned executables.

Keep the corpus and the original logs private. Ebira reads them locally; only
`ebira ask` sends anything out: the question and the text of the records it
reads, to the API you choose. Claude Code and Codex log format changes may
require an Ebira update.
