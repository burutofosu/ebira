# Ebira 0.4.0

`ebira ask` reads every message you wrote in the scope of a question, not only those that
hold the strings it searches for, and says what it did not read.

- Your own messages are few next to the agents' records: a few thousand in a history of a
  million records. So `ask` screens every one of them in the scope, the newest 4,000 at
  most, with the cheap model, and reads those that bear on the question. A decision in
  other words than any search string, a rule you repeated in different words, a later
  change of mind: these no longer depend on the strings the model chose. The check for
  later changes reads every later message of yours instead of searching for them.
- With `--cwd`, the scope is every message of the sessions that worked in that directory,
  also those written while a session was elsewhere.
- The result says what was not read: how many of your messages were screened and judged
  relevant, which sessions in the scope the records read come from, and, for a search
  string held by more records than were taken, the time before which none was read.
- The model that chooses the search strings sees a sample of your messages first, and
  chooses again when no record holds any of them.
- `--export <path>` writes the records the answer read and your relevant messages as text,
  to read elsewhere.
- `--no-sweep` asks as 0.3.1 did.

On the evaluation in `evals/`, now forty-two questions about made-up logs, `--quick` makes
99% of the key points of the original thirty (90% in 0.3.0), and the default models stay
at 100%. A question costs about a fifth more: about 35 to 45 US cents with the default
models, and still about a tenth of that with `--quick`. The
[measurements](https://github.com/burutofosu/ebira/blob/v0.4.0/evals/results/2026-10-19-sweep.md)
include six questions about the author's own history, where the screen found what the
search strings missed.

The result of `ebira ask` has new fields (`search.sweep`, `search.sweep_digest`,
`search.coverage`, and `oldest_taken` for a search string); a program that reads the
result may need updating.

See [CHANGELOG.md](https://github.com/burutofosu/ebira/blob/v0.4.0/CHANGELOG.md)
for the full list.

## Upgrading

The corpus stays as it is: no rebuild is needed.

## Install

From source, with Rust 1.89 or later:

```sh
cargo install --locked --git https://github.com/burutofosu/ebira --tag v0.4.0
ebira sync
```

For a binary archive, extract it and put `ebira` or `ebira.exe` on `PATH`.
SHA-256 checksums for both archives are listed in `SHA256SUMS.txt`.
The archives include the license, README, changelog, example transcript, and
agent skills.

## Agent skills

- Claude Code: copy the individual directories from `skills/claude` into `~/.claude/skills`.
- Codex: copy the individual directories from `skills/codex` into `~/.agents/skills`.

Keep each skill's `SKILL.md` and supporting files together. These locations
follow the [Claude Code skills guide](https://code.claude.com/docs/en/skills)
and the [Codex skills guide](https://learn.chatgpt.com/docs/build-skills).

## Compatibility and data

The package workflow builds Linux x86-64 and Windows x86-64 binaries, the
platforms verified for this release. The Linux build uses Ubuntu 22.04 and
glibc; it does not target musl-based distributions such as Alpine.

The binaries are unsigned.
Windows Smart App Control may block unsigned executables.

Keep the corpus and the original logs private. Ebira reads them locally; only
`ebira ask` sends anything out: the question and the text of the records it
reads, to the API you choose. Claude Code and Codex log format changes may
require an Ebira update.
