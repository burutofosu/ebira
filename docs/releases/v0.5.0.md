# Ebira 0.5.0

`ebira said --context` shows each of your messages with the agent's words around it, so that
a short reply says what it answers.

- "Go with that", "fixed!", "じゃあそうして": a short reply means nothing by itself. With
  `--context`, `said` shows under each message the end of the agent's reply before it and
  the agent's last reply in the turn it opened, each with a `source_ref` to read it whole.
  Tool calls, thinking, and the memory citations Codex appends are not replies, and a
  message or reply that Codex wrote twice counts once. On the author's history, 332 of the
  335 messages of twelve characters or fewer get the reply they answered, and a page takes
  as long as without it. The agent's words count toward `--max-chars`, so a page may hold
  fewer messages.
- The agent skills tell agents to read short replies with `--context`.
- For measuring `ask`: `--evidence-only` stops before the answer and writes what the answer
  would read and what the steps before it screened, and `evals/run.py --evidence` reports
  how far each record a question should cite gets. Ways of reading under trial, all off by
  default: `--sweep-context`, `--sweep-chunks`, `--turn-replies`, `--delivery spread`, and
  `--agent-select idf|all`. Three of them together handed over every record the
  evaluation's questions cite, where 0.4.0 lost some; whether the answers get better is not
  measured yet, so they stay off. The
  [measurements](https://github.com/burutofosu/ebira/blob/v0.5.0/evals/results/2026-10-20-delivery.md)
  say what each way kept and what it cost.
- Twelve more evaluation cases, on generated logs that each strain one step of `ask`: short
  agreements to an agent's proposal, a long pasted spec, hundreds of design remarks with
  three rules restated, and causes an agent found months ago.

Without the new options, `said` and `ask` write what they wrote in 0.4.0.

See [CHANGELOG.md](https://github.com/burutofosu/ebira/blob/v0.5.0/CHANGELOG.md)
for the full list.

## Upgrading

The corpus stays as it is: no rebuild is needed.

## Install

From source, with Rust 1.89 or later:

```sh
cargo install --locked --git https://github.com/burutofosu/ebira --tag v0.5.0
ebira sync
```

For a binary archive, extract it and put `ebira` or `ebira.exe` on `PATH`.
SHA-256 checksums for both archives are listed in `SHA256SUMS.txt`.
The archives include the license, README, changelog, example transcript, and
agent skills.

## Agent skills

- Claude Code: copy the individual directories from `skills/claude` into `~/.claude/skills`.
- Codex: copy the individual directories from `skills/codex` into `~/.agents/skills`.

Keep each skill's `SKILL.md` and supporting files together. These locations
follow the [Claude Code skills guide](https://code.claude.com/docs/en/skills)
and the [Codex skills guide](https://learn.chatgpt.com/docs/build-skills).

## Compatibility and data

The package workflow builds Linux x86-64 and Windows x86-64 binaries, the
platforms verified for this release. The Linux build uses Ubuntu 22.04 and
glibc; it does not target musl-based distributions such as Alpine.

The binaries are unsigned.
Windows Smart App Control may block unsigned executables.

Keep the corpus and the original logs private. Ebira reads them locally; only
`ebira ask` sends anything out: the question and the text of the records it
reads, to the API you choose. Claude Code and Codex log format changes may
require an Ebira update.
